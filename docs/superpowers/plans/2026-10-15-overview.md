# Overview Implementation Plan

**Goal:** Deliver the overview end to end: a mock aggregate `GET /v1/overview?period=week|month|year` in the base currency (total balance, income and expense totals with counts and change vs the previous range, spending by category for a donut, average expense, transaction count, budget figures of the current financial month with the per-day allowance and the top budgets, recent and today's transactions, a goals preview) and the `/` screen per `Main` / `Main-Dark` (header with the range label, week/month/year control and "Add transaction"; four stat cards; spending donut with PrimeVue `Chart`; quick add panel; budgets, recent transactions and goals cards) and `Mobile-Home` / `Mobile-Home-Dark` below `lg` (month left, per-day allowance, three budgets, today's transactions), with loading, error and empty states.

**Architecture:** The mock backend gains `mocks/overview.ts` (pure range, share and change rules plus `overviewOf`) and `mocks/handlers/overview.ts`. It reuses the stage 4–6 helpers instead of new sums: `transactionsIn` (extracted into `mocks/transactions.ts` and now also used by `spentByCategory`), `baseAmountOf`, `spentByCategory`, `budgetsOf`, `summarize`, `perDayHint`, `monthStartOf`, `goalsOf`, `amountIn`, `accountBalances` and `ownCategories`. On the frontend a new `app/features/overview` owns the API module, query keys, composables (aggregate query, URL range, range label, percent formatting), pure view helpers and the section components, all rendered from the aggregate DTO. The quick add panel is a new public component of `app/features/transactions` (it reuses that feature's form rules and mutation); `app/pages/index.vue` composes both features and opens the stage 4 dialog through `useTransactionDialog`.

**Tech Stack:** Nuxt 4, TypeScript strict, TanStack Query (`useQuery` with `keepPreviousData`), Vuelidate, PrimeVue 4 (`Chart` with Chart.js 4.5.1, `SelectButton`, `InputNumber`, `Select`, `DatePicker`, `InputText`, `Skeleton`, `Toast`), vue-i18n, Tailwind 4, Bun (`bun test`), Playwright, Biome.

**Spec:** `docs/superpowers/specs/2026-10-15-frontend-mocks-design.md` (section 1 rules on financial periods, transfers and budget per-day hint; section 2 aggregates, endpoints and invalidation; section 3 Overview screen; section 4 loading/error/empty behaviour; section 5 step 7 and the "EUR expense from a PLN card updates balance, overview and budget" E2E).

## Global Constraints

- Code, identifiers, commit messages in English; no comments except for a genuinely controversial decision; no tool attribution, no `Co-Authored-By` trailers, no mention of assistants anywhere (commits, PR, code, committed files).
- Conventional Commits; one commit per task with the message given in the task.
- API paths start with `/v1/`; errors are RFC 9457 ProblemDetails; validation messages are i18n keys under `validation.*`. The frontend never sends `userId`; every handler filters by the session user.
- `GET /v1/overview?period=` accepts `week | month | year` (default `month`); anything else is `400 { period: ['validation.invalidValue'] }`. `month` = the current financial period (`periodFor(today, monthStartDay)`), previous = the period before; `week` = the 7 days ending today inclusive, previous = the 7 days before; `year` = the 12 financial periods ending with the current one, previous = the 12 before.
- Income, expense (amount, count, change), spending slices, average expense, transaction count and recent transactions follow the selected range. `month` (planned, spent, left, days left, per-day allowance, budget count) and `topBudgets` always use the current financial month. The balance is always "now" (today's rate). Today's transactions are always today.
- All amounts are minor units in the user's base currency (`baseAmountOf` for transactions, `amountIn(…, today)` for account balances); `currency` in the DTO is the base currency.
- Transactions whose category is the `transfer` system category are excluded from every total, count, slice and list. Transfers are never income or expense.
- Spending slices: categories sorted by amount (desc, then name); the top 5 are named slices, every other category plus the system `other` category form one bucket (`categoryId: null`, `name: null`) shown as "Other"; percentages have one decimal and are rounded with the largest-remainder method on tenths so they sum to exactly 100.0. Slice colours follow rank: `chart-1` … `chart-5`, bucket `chart-6`.
- `change` = `round((current − previous) / previous × 100, 1 decimal)`, `null` when the previous amount is 0. `averageExpense` = `round(expense / count)`, `null` without expenses. `transactionCount` = income count + expense count.
- `perDay` = `perDayHint(left, daysLeft)` of the current month (`null` when nothing is left or no days remain). `topBudgets`: current-month budgets ordered by spent ÷ limit desc, then spent desc, at most 5 (desktop shows 5, mobile 3). `recent`: the 6 newest transactions of the range (date desc, then newest insert first). `today`: at most 10 of today's transactions, newest first. `goals`: at most 3, goals not reached first, creation order. `goalCount`: all goals. `hasTransactions`: the user has any transaction at all.
- Invalidation: `transactions`, `transfers`, `accounts`, `budgets`, `goals`, `goalContributions`, `categories` and `settings` all invalidate `['overview']` (already in the map; Task 2 pins it with a test). When goals exist the `settings` entry includes `['goals']` (it does).
- The range lives in the URL as `?range=week|month|year`, validated with fallback to `month` (like `isPeriodKey` for `?period=`).
- Consumers of `useUserSettings` must not format money with the PLN fallback while settings are pending or errored (gate on `isPending`/`isError` with a skeleton or `ErrorState`). The overview reads its currency from the DTO and the quick add panel from the selected account, so neither consumes `useUserSettings`.
- The UI never shows `ApiError.title` raw: unknown errors go through `useNotify().error` (status → `shared.error.*`), field errors through their i18n keys.
- Data queries run on the client only in mock mode — no `suspense()`, no server prefetch. The chart renders inside `<ClientOnly>`.
- Every user-facing string goes through i18n with keys in `en`, `pl`, `ru`, `uk` (the parity test enforces it); keys are camelCase; dates through `d()`, numbers and percentages through `n()`, money through `useMoney().format` / `MoneyText`; plural keys give 2 forms in `en` and 3 in `pl`, `ru`, `uk`.
- Accessibility: semantic elements, sections named by their heading or `aria-label`, labels for every input, `aria-invalid` + `aria-describedby` on invalid fields, focus moves to the first invalid field on submit, touch targets at least 44px (links styled `inline-flex min-h-11 items-center`), duplicated desktop/mobile blocks hidden with `display: none` (`hidden lg:flex`, `hidden! lg:flex!`, `lg:hidden!`) so only one is exposed. The donut canvas has `role="img"` and an `aria-label` listing every slice; a visually hidden table carries the same data; the visible legend is `aria-hidden`.
- Design tokens only, never hex values; chart colours are read from the `--mita-chart-*` and `--mita-surface` CSS variables at runtime and re-read when the `<html>` class changes (theme switch). Amounts and percentages use `font-mono`. Radius: 10px controls, 16px cards, 20px large panels.
- Features must not import other features' internals: `features/overview` renders from its own DTO; the quick add panel lives in `features/transactions`; the page composes both. Only libraries from `docs/STACK.md`; `chart.js` is added at the exact version `4.5.1` (published 2025-10-13) and `Chart` is removed from the PrimeVue exclude list in the same change. PrimeVue stays on 4.x.
- Code under `mocks/`, `app/shared/api/{contract,invalidation}.ts`, `app/shared/period` and `app/features/overview/utils` uses plain relative imports (no Nuxt auto-imports, no `~` alias) so it runs in Bun.
- Biome (`bun run lint`) and `nuxt typecheck` (0 `error TS` lines) must pass before every commit.
- Commands run inside WSL through `wsl.exe -d Debian -- bash /home/jaloqa/dock.mita-work/wsl-run.sh '<cmd>'`; E2E through `wsl.exe -d Debian -- bash /home/jaloqa/dock.mita-work/scripts/overview-e2e.sh [spec files]` (dev server on port 3100, Playwright container, both projects).

## Review Focus

- A financial month that does not start on the 1st (Oleh, day 10): the month and year ranges, the previous ranges and the budget month follow financial periods, not calendar months. Pinned in Task 1 (`rangesOf` with start 10, Oleh isolation test).
- The base currency changed after data exists: totals are re-priced at each transaction's date, balances at today's rate, the DTO currency follows the setting. Pinned in Task 1.
- Switching the theme while the donut is on screen: colours are re-read from the tokens and the chart re-renders instead of keeping light colours on a dark card. Pinned in Task 4 (E2E reads a pixel of the first slice before and after `emulateMedia({ colorScheme: 'dark' })` and expects it to match the light, then the dark `--mita-chart-1` token).
- A failed overview load: every aggregate section shows its own `ErrorState` with retry, one retry recovers all of them (they share one query), the header stays usable and the quick add panel has its own independent error and retry. Pinned in Task 3, Task 5 and Task 6 (E2E with the mock error simulation).
- A brand-new user with no accounts, transactions, budgets or goals sees an empty state in every section instead of zeros. Pinned in Task 3, Task 4 and Task 6 (E2E on a stored mock DB stripped of the user's data).
- An unknown `?range=` in the URL or an invalid `period` sent to the API: the screen falls back to the month, the API answers 400. Pinned in Task 1 (unit) and Task 3 (E2E).
- A transaction saved anywhere — header dialog, quick add panel, mobile keypad — refreshes the overview cards, the account balance and the budget without a reload. Pinned in Task 5, Task 6 and Task 7 (E2E).

## Decisions taken for this stage

- **Feature placement:** a new `app/features/overview` (API, keys, composables, view helpers, section components) renders everything from the aggregate DTO, so it never imports budgets, goals or transactions internals. The quick add panel is a new public component `QuickAddPanel` of `features/transactions` (it needs that feature's Vuelidate rules and `useTransactionMutations`); the page composes it, and opens the stage 4 dialog through `useTransactionDialog` like the transactions page and the layout already do. Nothing moves into `shared/`.
- **Range control:** `?range=week|month|year` in the URL, validated with fallback to `month`; the API query parameter keeps the spec's name `period`. Week = last 7 days ending today, year = 12 financial periods ending with the current one; budget figures always use the current financial month and their labels name it ("Budgets for October", "Budgets · October", "Left this month").
- **Header:** desktop eyebrow "Overview", `h1` = the range label (`shared.period.range` with `d()`: "Oct 1 – Oct 31, 2026"; the start date shows its year only when the years differ). Mobile eyebrow "Budget for", `h1` = the current financial month name; the design's calendar button is a 44px link to `/budgets` ("Budgets by period"), where periods are switched.
- **Donut:** top 5 categories plus one "Other" bucket that also absorbs the system "other" category; slice colours by rank (`chart-1`…`chart-5`, bucket `chart-6`), matching the design order, because several categories share a colour token. One-decimal percentages, largest-remainder rounding, sum exactly 100.0.
- **Change vs previous range:** expense change in the donut footer ("vs September", "vs previous 7 days", "vs previous 12 months"), income change appended to the income card footer; "—" when the previous range had nothing.
- **Average expense:** expense total ÷ expense count, rounded to a minor unit; "—" without expenses.
- **Top budgets:** 5 on desktop (the design lists five), 3 on mobile; ordered by share spent. Bars use `ink` when over budget, `accent` otherwise (stage 5 ruling).
- **Recent / today:** 6 newest transactions of the range on desktop, up to 10 of today's on mobile; rows show the title (category name when empty), "Category · today/yesterday/Oct 3" on desktop and "Category · Account" on mobile; rows are not interactive, "All" links to `/transactions`.
- **Goals preview:** first 3 goals that are not reached (creation order), then reached ones; bar `ink`, "{saved} of {target} · Deadline: June 2027", "Reached" for reached goals; "New goal" links to `/goals`.
- **Balance:** active accounts only, each converted at today's rate (archived accounts are excluded, as on the accounts screen); footer "N accounts".
- **Errors and loading:** the aggregate is one query; each section shows its own skeleton while it loads and, when the query fails without cached data (`failed = isError && !overview`), its own `ErrorState` with retry (components take `failed?: boolean` and emit `retry`; the page answers every `retry` with the one `refetch`, so one click recovers all sections — accepted cost: several retry buttons on screen at once). Sections inside a card use the new `compact` variant of the shared `ErrorState` (no own surface, smaller padding); the summary grid uses the regular one across all columns. The header, the "Add transaction" button and the quick add panel (its own queries) keep working. With cached data a failed refetch keeps showing the data.
- **Empty states for a brand-new user:** no accounts → an `EmptyState` above the sections with "Add an account" (`/accounts`); no transactions → the spending card shows "No transactions yet" with "Add your first transaction" (opens the dialog), recent shows "No transactions yet."; no budgets this month → "No budgets for this month." with "Create a budget" (`/budgets`) in the budgets cards and the budget-left card; no goals → "No goals yet." with "Create a goal" (`/goals`); mobile with no budgets shows the total balance instead of "Left this month" and hides the per-day row; with budgets but nothing left (`perDay` is `null`) the per-day row shows "—"; nothing today → "No transactions today." with "Add a transaction" (`/transactions/new`).
- **Failure and empty states in E2E:** the mock's error simulation (`simulateErrors`, toggled by `PUT /v1/demo/simulate-errors`, which no screen exposes) fails 20% of non-demo requests at random and cannot target one endpoint. The specs therefore persist the mock DB with one save (the header dialog on desktop, the keypad on mobile), set `simulateErrors: true` in `localStorage['mita-mock-db-v1']` and pin `Math.random` with `addInitScript` (0 → every request fails; 0.99 after `recover()` sets a window flag → none fails). Every query on `/` fails, so the quick add panel's own error and retry are pinned in a separate test. The brand-new user is the active demo user with their accounts, transactions, transfers, budgets, goals and contributions removed from the stored DB (categories and settings stay), then a reload. Recorded gap: the loading skeletons are not pinned by E2E (timing-dependent with the mock delay of 150–400 ms).
- **Copy reuse:** strings the transactions screen already has are not duplicated: the header button uses `transactions.actions.add`, the spending empty state `transactions.empty.title` and `transactions.actions.addFirst`.
- **Quick add panel:** expense/income toggle, amount in the selected account's currency, category, date, account, note, Save; validated with the existing `transactionRules` (cross-currency off); success → toast "Transaction saved" and reset of amount, note and date (kind, category and account stay); field errors from the server are mapped, others go to the toast. Disabled-state handling mirrors the dialog: loading skeleton, `ErrorState` with retry only when a list failed and is empty (`isError && list.length === 0`, so cached lists keep the form usable), "Add an account first".
- **Chart:** PrimeVue `Chart` (`type="doughnut"`, cutout 70%, legend off, tooltip with the formatted amount) inside `<ClientOnly>`; colours read from CSS variables on mount and on every `<html>` class change through a `MutationObserver` (no timing assumptions about when the theme class lands). Canvas `role="img"` + `aria-label`, a `sr-only` table, the visible legend `aria-hidden`.
- **Settings gating:** the page does not consume `useUserSettings`; the DTO carries the base currency, so no money is formatted with the PLN fallback.
- **No new tables:** the aggregate is computed on read; `MockState` and the seed are unchanged.

```ts
} from '../app/shared/api/contract'

import { addDaysIso, daysLeft, type MonthStart, type Period, periodFor, shiftPeriod } from '../app/shared/period/period'
import { budgetsOf, monthStartOf, perDayHint, spentByCategory, summarize } from './budgets'

export const SPENDING_SLICES = 5
export const TOP_BUDGETS = 5
export const RECENT_TRANSACTIONS = 6
export const TODAY_TRANSACTIONS = 10
export const GOALS_PREVIEW = 3

export type DateRange = Pick<Period, 'from' | 'to'>

export type RangePair = { current: DateRange; previous: DateRange }

type Categories = ReadonlyMap<string, Pick<CategoryRow, 'name' | 'system'>>

type KindTotal = { amount: number; count: number }

type Totals = Record<TransactionRow['kind'], KindTotal>

export function rangesOf(range: OverviewRange, today: string, monthStart: MonthStart): RangePair {
  if (range === 'week') {
    return {
      current: { from: addDaysIso(today, -6), to: today },
      previous: { from: addDaysIso(today, -13), to: addDaysIso(today, -7) },
    }
  }
  const period = periodFor(today, monthStart)
  const span = (first: number, last: number): DateRange => ({
    from: shiftPeriod(period.key, first, monthStart).from,
    to: shiftPeriod(period.key, last, monthStart).to,
  })
  return range === 'month'
    ? { current: span(0, 0), previous: span(-1, -1) }
    : { current: span(-11, 0), previous: span(-23, -12) }
}

export function percentChange(current: number, previous: number): number | null {
  if (previous === 0) return null
  return Math.round(((current - previous) * 1000) / previous) / 10
}

export function shareTenths(amounts: readonly number[]): number[] {
  const total = amounts.reduce((sum, amount) => sum + amount, 0)
  if (total <= 0) return amounts.map(() => 0)
  const exact = amounts.map((amount) => (amount * 1000) / total)
  const tenths = exact.map((value) => Math.floor(value))
  let rest = 1000 - tenths.reduce((sum, value) => sum + value, 0)
  const byFraction = exact
    .map((value, index) => ({ index, fraction: value - Math.floor(value) }))
    .sort((a, b) => b.fraction - a.fraction || a.index - b.index)
  for (const { index } of byFraction) {
    if (rest <= 0) break
    tenths[index] = (tenths[index] ?? 0) + 1
    rest -= 1
  }
  return tenths
}

export function spendingSlices(spent: ReadonlyMap<string, number>, categories: Categories): SpendingSlice[] {
  let bucket = 0
  const named: { categoryId: string; name: string; amount: number }[] = []
  for (const [categoryId, amount] of spent) {
    const category = categories.get(categoryId)
    if (amount <= 0 || category?.system === 'transfer') continue
    if (!category || category.system === 'other') bucket += amount
    else named.push({ categoryId, name: category.name, amount })
  }
  named.sort((a, b) => b.amount - a.amount || a.name.localeCompare(b.name))
  const top = named.slice(0, SPENDING_SLICES)
  for (const entry of named.slice(SPENDING_SLICES)) bucket += entry.amount
  const tenths = shareTenths([...top.map((entry) => entry.amount), ...(bucket > 0 ? [bucket] : [])])
  const slices: SpendingSlice[] = top.map((entry, index) => ({ ...entry, percent: (tenths[index] ?? 0) / 10 }))
  if (bucket > 0) {
    slices.push({ categoryId: null, name: null, amount: bucket, percent: (tenths[top.length] ?? 0) / 10 })
  }
  return slices
}

function totalsOf(state: MockState, rows: readonly TransactionRow[], base: Currency): Totals {
  const totals: Totals = { income: { amount: 0, count: 0 }, expense: { amount: 0, count: 0 } }
  for (const row of rows) {
    totals[row.kind].amount += baseAmountOf(state, row, base)
    totals[row.kind].count += 1
  }
  return totals
}

const withChange = (current: KindTotal, previous: KindTotal): OverviewTotal => ({
  ...current,
  change: percentChange(current.amount, previous.amount),
})

const newestFirst = (rows: readonly TransactionRow[]): TransactionRow[] =>
  rows
    .map((row, index) => ({ row, index }))
    .sort((a, b) => b.row.date.localeCompare(a.row.date) || b.index - a.index)
    .map((entry) => entry.row)

function balanceOf(state: MockState, userId: string, base: Currency, today: string): OverviewDto['balance'] {
  const balances = accountBalances(state, userId)
  const active = state.accounts.filter((row) => row.userId === userId && !row.archived)
  return {
    amount: active.reduce(
      (sum, row) => sum + amountIn(state, balances.get(row.id) ?? row.openingBalance, row.currency, base, today),
      0,
    ),
    accounts: active.length,
  }
}

const usage = (budget: { spent: number; limit: number }): number => (budget.limit > 0 ? budget.spent / budget.limit : 0)

export function overviewOf(db: MockDb, userId: string, range: OverviewRange, today: string): OverviewDto {
  const { state } = db
  const base = baseCurrencyOf(state, userId)
  const monthStart = monthStartOf(state, userId)
  const categories: Categories = new Map(ownCategories(db, userId).map((row) => [row.id, row]))
  const accountNames = new Map(state.accounts.filter((row) => row.userId === userId).map((row) => [row.id, row.name]))
  const counted = (window: DateRange) =>
    transactionsIn(state, userId, window).filter((row) => categories.get(row.categoryId)?.system !== 'transfer')
  const transactionView = (row: TransactionRow): OverviewTransactionDto => ({
    id: row.id,
    kind: row.kind,
    date: row.date,
    title: row.title,
    categoryName: categories.get(row.categoryId)?.name ?? '',
    accountName: accountNames.get(row.accountId) ?? '',
    amount: baseAmountOf(state, row, base),
  })

  const { current, previous } = rangesOf(range, today, monthStart)
  const rows = counted(current)
  const now = totalsOf(state, rows, base)
  const before = totalsOf(state, counted(previous), base)

  const period = periodFor(today, monthStart)
  const days = daysLeft(period, today)
  const budgets = budgetsOf(state, userId, period, today)
  const summary = summarize(budgets, days)
  const topBudgets: OverviewBudgetDto[] = [...budgets]
    .sort((a, b) => usage(b) - usage(a) || b.spent - a.spent)
    .slice(0, TOP_BUDGETS)
    .map((row) => ({
      id: row.id,
      categoryId: row.categoryId,
      name: categories.get(row.categoryId)?.name ?? '',
      limit: row.limit,
      spent: row.spent,
      remaining: row.remaining,
      status: row.status,
    }))

  const goals = goalsOf(state, userId, today)
  const preview: OverviewGoalDto[] = [
    ...goals.filter((row) => row.status !== 'reached'),
    ...goals.filter((row) => row.status === 'reached'),
  ]
    .slice(0, GOALS_PREVIEW)
    .map((row) => ({
      id: row.id,
      name: row.name,
      target: row.target,
      saved: row.saved,
      percent: row.percent,
      status: row.status,
      deadline: row.deadline,
    }))

  return {
    range,
    from: current.from,
    to: current.to,
    previousFrom: previous.from,
    previousTo: previous.to,
    currency: base,
    balance: balanceOf(state, userId, base, today),
    income: withChange(now.income, before.income),
    expense: withChange(now.expense, before.expense),
    averageExpense: now.expense.count > 0 ? Math.round(now.expense.amount / now.expense.count) : null,
    transactionCount: now.income.count + now.expense.count,
    spending: spendingSlices(spentByCategory(state, userId, base, current), categories),
    month: {
      period: period.key,
      from: period.from,
      to: period.to,
      planned: summary.planned,
      spent: summary.spent,
      left: summary.left,
      daysLeft: days,
      perDay: perDayHint(summary.left, days),

    today: newestFirst(counted({ from: today, to: today })).slice(0, TODAY_TRANSACTIONS).map(transactionView),
    goals: preview,
    goalCount: goals.length,
    hasTransactions: state.transactions.some((row) => row.userId === userId),
  }
}
```

```ts
import { type BudgetStatus, type CategoryColor, isOverviewRange, type OverviewRange } from '../../../shared/api/contract'
import { addDaysIso, shiftPeriod } from '../../../shared/period/period'

const SLICE_COLORS: readonly CategoryColor[] = ['chart-1', 'chart-2', 'chart-3', 'chart-4', 'chart-5']

export const resolveOverviewRange = (value: unknown): OverviewRange => (isOverviewRange(value) ? value : 'month')

export const sliceColor = (index: number, bucket: boolean): CategoryColor =>
  bucket ? 'chart-6' : (SLICE_COLORS[index] ?? 'chart-5')

export const sameYear = (from: string, to: string): boolean => from.slice(0, 4) === to.slice(0, 4)

export const previousMonthKey = (key: string): string => shiftPeriod(key, -1, 1).key

export type DayLabel = 'today' | 'yesterday' | 'date'

export function dayLabelOf(date: string, today: string): DayLabel {
  if (date === today) return 'today'
  return date === addDaysIso(today, -1) ? 'yesterday' : 'date'
}

export const usedShare = (spent: number, limit: number): number => (limit > 0 ? spent / limit : 0)

export const budgetTone = (status: BudgetStatus): 'accent' | 'ink' => (status === 'over_budget' ? 'ink' : 'accent')

export const initialOf = (text: string): string => Array.from(text.trim())[0]?.toLocaleUpperCase() ?? ''
```

```ts
import { keepPreviousData, useQuery } from '@tanstack/vue-query'
import type { MaybeRefOrGetter } from 'vue'
import type { OverviewRange } from '~/shared/api/contract'
import { overviewKeys } from '../api/keys'
import { overviewApi } from '../api/overviewApi'

export function useOverview(range: MaybeRefOrGetter<OverviewRange>) {
  const api = overviewApi(useApi())
  const query = useQuery({
    queryKey: computed(() => overviewKeys.range(toValue(range))),
    queryFn: ({ queryKey }) => api.get(queryKey[1]),
```

```vue
<script setup lang="ts">
import type { OverviewTransactionDto } from '~/shared/api/contract'
import type { Currency } from '~/shared/money/money'
import { dayLabelOf, initialOf } from '../utils/overviewView'

const props = defineProps<{
  items: OverviewTransactionDto[]
  currency: Currency
  meta: 'date' | 'account'
  today: string
}>()
const { t, d } = useI18n()

const titleOf = (item: OverviewTransactionDto) => item.title || item.categoryName

function whenOf(date: string) {
  const label = dayLabelOf(date, props.today)
  if (label !== 'date') return t(`overview.recent.${label}`)
  return d(new Date(`${date}T00:00:00Z`), { day: 'numeric', month: 'short', timeZone: 'UTC' })
}

const metaOf = (item: OverviewTransactionDto) =>
  t('overview.recent.meta', {
    category: item.categoryName,
    detail: props.meta === 'date' ? whenOf(item.date) : item.accountName,
  })
</script>

<template>
  <ul class="m-0 flex list-none flex-col p-0">
    <li v-for="item in items" :key="item.id" class="flex items-center gap-3 border-t border-bg py-2.5">
      <span
        class="flex size-9 shrink-0 items-center justify-center rounded-(--radius-control) bg-track text-[13px] font-bold text-ink"
        aria-hidden="true"
      >
        {{ initialOf(titleOf(item)) }}
      </span>
      <div class="flex min-w-0 flex-auto flex-col gap-0.5">
        <span class="truncate text-sm font-medium">{{ titleOf(item) }}</span>
        <span class="truncate text-xs text-muted">{{ metaOf(item) }}</span>
      </div>
      <MoneyText
        class="text-sm"
        :amount="item.kind === 'income' ? item.amount : -item.amount"

  </ul>
</template>
```

```ts
const ringPixel = (canvas: Locator) =>
  canvas.evaluate((element: HTMLCanvasElement) => {
    const scale = element.width / element.clientWidth
    const radius = (element.clientWidth / 2) * 0.85
    const angle = (20 * Math.PI) / 180
    const x = Math.round((element.clientWidth / 2 + radius * Math.sin(angle)) * scale)
    const y = Math.round((element.clientHeight / 2 - radius * Math.cos(angle)) * scale)
    return Array.from(element.getContext('2d')?.getImageData(x, y, 1, 1).data ?? [])
  })

const tokenPixel = (page: Page, token: string) =>
  page.evaluate((name) => {
    const context = document.createElement('canvas').getContext('2d')
    if (!context) return []
    context.fillStyle = getComputedStyle(document.documentElement).getPropertyValue(name).trim()
    context.fillRect(0, 0, 1, 1)
    return Array.from(context.getImageData(0, 0, 1, 1).data)
  }, `--mita-${token}`)
```

```ts
const amountOf = (text: string | null) => Number((text ?? '').replace(/[^\d.-]/g, ''))
const moneyOf = async (locator: Locator) => amountOf(await locator.locator('.font-mono').first().textContent())
const card = (page: Page, name: string) =>
  page.getByRole('article').filter({ has: page.getByRole('heading', { name, exact: true }) })

test('a EUR expense from a PLN card updates the account, the overview and the budget', async ({
  page,
  isMobile,
}) => {
  test.skip(isMobile, 'currency and rate are picked in the desktop dialog')
  await page.goto('/budgets')
  const gifts = card(page, 'Prezenty')
  await expect(gifts).toContainText('of PLN 500.00')
  const giftsBefore = await moneyOf(gifts)
  await page.goto('/accounts')
  await expect(card(page, 'Konto główne')).toContainText('PLN 8,820.40')

  await page.goto('/')
  const summary = page.getByRole('region', { name: 'Summary', exact: true })
  const balance = summary.getByTestId('overview-balance')
  const expense = summary.getByTestId('overview-expense')
  const left = summary.getByTestId('overview-budget-left')
  await expect(balance).toContainText(/PLN\s[\d,]+\.\d{2}/)
  const balanceBefore = await moneyOf(balance)
  const expenseBefore = await moneyOf(expense)
  const leftBefore = await moneyOf(left)
  const countBefore = Number((await expense.innerText()).match(/(\d+) transactions?/)?.[1])

  await page.getByRole('button', { name: 'Add transaction' }).click()
  const dialog = page.getByRole('dialog', { name: 'New transaction' })
  await expect(dialog.getByRole('combobox', { name: 'Account' })).toContainText('Konto główne · PLN')
  await dialog.getByLabel('Amount').pressSequentially('50')
  await dialog.getByRole('combobox', { name: 'Currency' }).click()
  await page.getByRole('option', { name: 'EUR', exact: true }).click()
  const rate = dialog.getByLabel('Exchange rate (EUR → PLN)')
  await expect(rate).toHaveValue(/^4\.\d+$/)
  await rate.fill('')
  await rate.pressSequentially('4')
  await expect(dialog.getByText('On the account: PLN 200.00')).toBeVisible()
  await dialog.getByRole('combobox', { name: 'Category' }).click()
  await page.getByRole('option', { name: 'Prezenty', exact: true }).click()
  await dialog.getByRole('button', { name: 'Save' }).click()
  await expect(dialog).toBeHidden()
  await expect(page.getByText('Transaction saved')).toBeVisible()

  await expect.poll(() => moneyOf(balance)).toBeCloseTo(balanceBefore - 200, 2)
  await expect.poll(() => moneyOf(expense)).toBeCloseTo(expenseBefore + 200, 2)
  await expect.poll(() => moneyOf(left)).toBeCloseTo(leftBefore - 200, 2)
  await expect(expense).toContainText(`${countBefore + 1} transactions`)

  await page.goto('/accounts')
  await expect(card(page, 'Konto główne')).toContainText('PLN 8,620.40')
  await page.goto('/budgets')
  await expect(gifts).toContainText('of PLN 500.00')
  await expect.poll(() => moneyOf(gifts)).toBeCloseTo(giftsBefore + 200, 2)
})
```
