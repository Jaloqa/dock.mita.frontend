# Budgets Implementation Plan

**Goal:** Deliver budgets end to end: the mock backend (`Budget` per user and financial period with spent, remaining, status, per-day hint and a period summary, validation, copy from the previous period, category-deletion merge, seeded history for both demo users) and the `/budgets` screen (period switcher kept in the URL, dark summary card, category cards, new/edit/delete dialog, "add category" tile, copy from the previous period, loading/empty/error states).

**Architecture:** The mock backend gains a `budgets` table, pure budget rules in `mocks/budgets.ts` (status, per-day hint, limit conversion, spent per category, period summary, a `categoryReferences` entry that merges colliding "other" budgets) and handlers for `/v1/budgets`. Budgets are keyed by the financial period key (`YYYY-MM`), so a month-start change re-ranges the same key, and each row stores the base currency its limit was entered in, so a base-currency change converts it at the period-start rate on read (same approach as transactions). On the frontend `app/features/budgets` owns the API module, query keys, composables (list per period, mutations, URL period, screen state), pure view helpers, Vuelidate rules and components; `app/pages/budgets.vue` composes them with the category manager dialog from `features/categories`.

**Tech Stack:** Nuxt 4, TypeScript strict, TanStack Query (`useQuery`, `useMutation`), Vuelidate, PrimeVue 4 (`Dialog`, `Select`, `SelectButton`, `InputNumber`, `InputText`, `Skeleton`, `Toast`, `ConfirmDialog`), vue-i18n, Tailwind 4, Bun (`bun test`), Playwright, Biome.

**Spec:** `docs/superpowers/specs/2026-10-15-frontend-mocks-design.md` (section 1 `Budget` and the status / per-day rules, section 2 endpoints and invalidation, section 3 Budgets screen, section 4 forms and errors, section 5 step 5).

## Global Constraints

- Code, identifiers, commit messages in English; no comments except for a genuinely controversial decision; no tool attribution and no `Co-Authored-By` trailers in commits or files.
- API paths start with `/v1/`; errors are RFC 9457 ProblemDetails; validation messages are i18n keys under `validation.*`.
- The frontend never sends `userId`; every handler filters by the session user; a foreign or missing id returns `404`.
- `Budget` = `id`, `userId`, `categoryId`, `period` (`YYYY-MM` financial period key), `limit` (minor units, base currency). Stored rows also keep `currency` (the base currency the limit was entered in).
- Status: spent below 85% of the limit `on_track`, 85–100% `almost_spent`, above 100% `over_budget`. Per-day hint = remaining / days left in the period (floored to a minor unit), `null` when nothing remains or no days are left.
- Spent = base-currency sum of the user's expense transactions of that category with a date inside the financial period (`monthStartDay`). Transfers are never counted.
- One budget per category per period (`validation.budgetExists`); expense categories only (`validation.expenseCategoryOnly`); the `transfer` system category and foreign/unknown categories are `validation.unknownCategory`; limit > 0 (`validation.positiveAmount`), integer at most `100_000_000_000` minor units (`validation.invalidValue`).
- Deleting a category moves its budgets to "other"; when "other" already has a budget in the same period the limits are added up (in the current base currency) and the moved row disappears.
- Lists are paginated (`{ items, page, pageSize, total }`); `GET /v1/budgets` adds `period`, `from`, `to`, `currency`, `summary { planned, spent, left, daysLeft }`.
- A budget change invalidates `budgets` and `overview`; transaction, category and settings changes already invalidate `budgets`.
- Period keys from the URL are validated with `isPeriodKey` and fall back to the current period.
- Every user-facing string goes through i18n with keys in `en`, `pl`, `ru`, `uk` (the parity test enforces it); keys are camelCase.
- The UI never shows `ApiError.title` raw: unknown errors map by status (`useNotify().error`), field errors are shown through their i18n keys.
- Consumers of `useUserSettings` gate on `isPending` / `isError` before using `monthStart` or the base currency; money is never formatted with the PLN fallback.
- Data queries run on the client only in mock mode — no `suspense()` or server prefetch.
- Accessibility: semantic elements, labels for every input, `aria-invalid` + `aria-describedby` on invalid fields, focus moves to the first invalid field on submit, touch targets at least 44px.
- Only libraries from `docs/STACK.md`; PrimeVue stays on 4.x; components use design tokens, never raw hex values; amounts use `font-mono`.
- Code under `mocks/`, `app/shared/api/{contract,invalidation}.ts`, `app/shared/period`, `app/features/budgets/utils` and `app/features/budgets/schemas` uses plain relative imports (no Nuxt auto-imports, no `~` alias) so it runs in Bun.
- Biome (`bun run lint`) and `nuxt typecheck` (0 `error TS` lines) must pass before every commit.

## Review Focus

- Changing the base currency after budgets exist: limits entered in the old currency are converted at the rate of the period's first day, spent follows the transactions' base amounts, and an edit stores the limit in the new base currency. Pinned in Task 1.
- Changing the month start keeps the same period key but re-ranges it; spent is recomputed for the new range and the default period follows the new start. Pinned in Task 1.
- Deleting a category whose budget collides with an "other" budget in the same period merges the limits instead of leaving two "other" budgets. Pinned in Task 1.
- A malformed `?period=` (`2026-13`, `abc`, `0000-01`, an array) never reaches the API; the screen shows the current period. Pinned in Task 1 (`isPeriodKey`), Task 3 (`resolvePeriodKey`) and Task 4 (E2E).
- Oleh's month start is the 10th: his seeded budgets sit on his own period keys and his current period is computed with his start. Pinned in Task 2.
- A past period shows 0 days left and no per-day hint; an overspent card shows "Overspent" instead of a negative "Left". Pinned in Task 1 and Task 5.

## Decisions taken for this stage

- "Add category" tile: opens the new-budget dialog (it adds a category to the budget of this period). When every expense category already has a budget, the dialog explains it and offers "Manage categories", which opens the existing category manager.
- "Copy budgets from previous period": offered in the empty state only when the previous period has budgets; implemented as `POST /v1/budgets/copy` `{ period }` → `{ copied }` (atomic in the backend, skips categories that already have a budget, `400 period: validation.nothingToCopy` when nothing would be copied). This endpoint is not in the spec's endpoint table.
- Seeded limits: Anna gets the design's eight limits (total 7 000 zł) for the current and three previous periods; spent comes from her seeded transactions, so it does not equal the design's sample spent values. Oleh gets eight UAH limits sized to his seeded spending.
- Cards keep the creation order of the budgets (the design lists them that way).

import { describe, expect, it } from 'bun:test'
import type { BudgetDto, BudgetPage, CategoryDto, Page } from '../../../app/shared/api/contract'
import { convertMinor } from '../../../app/shared/money/money'
import { addDaysIso, daysLeft, periodByKey, periodFor, shiftPeriod, todayIso } from '../../../app/shared/period/period'

const current = periodFor(today, 1)
const previous = shiftPeriod(current.key, -1, 1)

const groceries = 'cat_anna_expense_groceries'
const cafes = 'cat_anna_expense_cafes'

import type { BudgetDto, BudgetStatus, BudgetSummary } from '../app/shared/api/contract'
import { type Currency, convertMinor } from '../app/shared/money/money'
import { daysLeft, type MonthStart, type Period, periodByKey } from '../app/shared/period/period'
import type { CategoryReference } from './categories'
import type { BudgetRow, MockState } from './db'
import { rateOn } from './rates'
import { baseAmountOf, baseCurrencyOf } from './transactions'

export function budgetStatus(spent: number, limit: number): BudgetStatus {
  if (spent > limit) return 'over_budget'
  if (spent * 100 >= limit * 85) return 'almost_spent'
  return 'on_track'
}

export const perDayHint = (remaining: number, days: number): number | null =>
  remaining > 0 && days > 0 ? Math.floor(remaining / days) : null

export const monthStartOf = (state: MockState, userId: string): MonthStart =>
  state.settings.find((row) => row.userId === userId)?.monthStartDay ?? 1

export const limitIn = (state: MockState, row: BudgetRow, base: Currency, period: Period): number =>
  row.currency === base ? row.limit : convertMinor(row.limit, rateOn(state.rates, period.from, row.currency, base))

export function spentByCategory(
  state: MockState,
  userId: string,
  base: Currency,
  period: Period,
): Map<string, number> {
  const spent = new Map<string, number>()
  for (const row of state.transactions) {
    if (row.userId !== userId || row.kind !== 'expense' || row.date < period.from || row.date > period.to) continue
    spent.set(row.categoryId, (spent.get(row.categoryId) ?? 0) + baseAmountOf(state, row, base))
  }
  return spent
}

export function budgetsOf(state: MockState, userId: string, period: Period, today: string): BudgetDto[] {
  const base = baseCurrencyOf(state, userId)
  const spent = spentByCategory(state, userId, base, period)
  const days = daysLeft(period, today)
  return state.budgets
    .filter((row) => row.userId === userId && row.period === period.key)
    .map((row) => {
      const limit = limitIn(state, row, base, period)
      const used = spent.get(row.categoryId) ?? 0
      const remaining = limit - used
      return {
        id: row.id,
        categoryId: row.categoryId,
        period: row.period,
        limit,
        spent: used,
        remaining,
        status: budgetStatus(used, limit),
        perDay: perDayHint(remaining, days),
      }
    })
}

export function summarize(budgets: readonly BudgetDto[], days: number): BudgetSummary {
  const planned = budgets.reduce((sum, budget) => sum + budget.limit, 0)
  const spent = budgets.reduce((sum, budget) => sum + budget.spent, 0)
  return { planned, spent, left: planned - spent, daysLeft: days }
}

export const budgetReference: CategoryReference = {
  usedCategoryIds: (state, userId) =>
    new Set(state.budgets.filter((row) => row.userId === userId).map((row) => row.categoryId)),
  reassign: (state, userId, fromId, toId) => {
    const base = baseCurrencyOf(state, userId)
    const monthStart = monthStartOf(state, userId)
    const merged = new Set<string>()
    for (const row of state.budgets) {
      if (row.userId !== userId || row.categoryId !== fromId) continue
      const target = state.budgets.find(
        (candidate) => candidate.userId === userId && candidate.categoryId === toId && candidate.period === row.period,
      )
      if (!target) {
        row.categoryId = toId
        continue
      }
      const period = periodByKey(row.period, monthStart)
      target.limit = limitIn(state, target, base, period) + limitIn(state, row, base, period)
      target.currency = base
      merged.add(row.id)
    }
    state.budgets = state.budgets.filter((row) => !merged.has(row.id))
  },
}

import type { BudgetCopyResult, BudgetDto, BudgetPage } from '../../app/shared/api/contract'
import { daysLeft, isPeriodKey, periodByKey, periodFor, shiftPeriod, todayIso } from '../../app/shared/period/period'
import { budgetsOf, limitIn, monthStartOf, summarize } from '../budgets'
import { ownCategories } from '../categories'
import type { BudgetRow, MockDb } from '../db'
import { badRequest, notFound } from '../errors'
import { newId } from '../ids'
import { paginate } from '../paginate'
import type { MockRouter } from '../router'
import { baseCurrencyOf } from '../transactions'
import { collectErrors, isMissing, objectBody } from '../validation'

export const BUDGET_LIMIT_MAX = 100_000_000_000

type Fields = Pick<BudgetRow, 'categoryId' | 'period' | 'limit'>

function validateBudget(db: MockDb, userId: string, body: unknown, existing?: BudgetRow): Fields {
  const { categoryId, period, limit } = objectBody(body)
  const errors = collectErrors()
  if (isMissing(period)) errors.add('period', 'validation.required')
  else if (!isPeriodKey(period)) errors.add('period', 'validation.invalidValue')
  if (isMissing(categoryId)) errors.add('categoryId', 'validation.required')
  else {
    const category = ownCategories(db, userId).find((row) => row.id === categoryId)
    if (!category || category.system === 'transfer') errors.add('categoryId', 'validation.unknownCategory')
    else if (category.kind !== 'expense') errors.add('categoryId', 'validation.expenseCategoryOnly')
    else if (
      isPeriodKey(period) &&
      db.state.budgets.some(
        (row) =>
          row.userId === userId && row.id !== existing?.id && row.categoryId === categoryId && row.period === period,
      )
    ) {
      errors.add('categoryId', 'validation.budgetExists')
    }
  }
  if (isMissing(limit)) errors.add('limit', 'validation.required')
  else if (!Number.isSafeInteger(limit) || (limit as number) > BUDGET_LIMIT_MAX) {
    errors.add('limit', 'validation.invalidValue')
  } else if ((limit as number) <= 0) errors.add('limit', 'validation.positiveAmount')
  errors.throwIfAny()
  return { categoryId: categoryId as string, period: period as string, limit: limit as number }
}

const ownBudget = (db: MockDb, userId: string, id: string | undefined): BudgetRow =>
  db.state.budgets.find((row) => row.id === id && row.userId === userId) ?? notFound()

const viewOf = (db: MockDb, userId: string, row: BudgetRow): BudgetDto =>
  budgetsOf(db.state, userId, periodByKey(row.period, monthStartOf(db.state, userId)), todayIso()).find(
    (budget) => budget.id === row.id,
  ) ?? notFound()

function readPeriod(value: unknown): string {
  if (isMissing(value)) badRequest({ period: ['validation.required'] })
  if (!isPeriodKey(value)) badRequest({ period: ['validation.invalidValue'] })
  return value as string
}

export function registerBudgetHandlers(router: MockRouter) {
  router.on('GET', '/v1/budgets', ({ db, userId, query }): BudgetPage => {
    if (query.period !== undefined && !isPeriodKey(query.period)) badRequest({ period: ['validation.invalidValue'] })
    const today = todayIso()
    const monthStart = monthStartOf(db.state, userId)
    const period = query.period === undefined ? periodFor(today, monthStart) : periodByKey(query.period, monthStart)
    const budgets = budgetsOf(db.state, userId, period, today)
    return {
      ...paginate(budgets, query, { defaultPageSize: 100, maxPageSize: 100 }),
      period: period.key,
      from: period.from,
      to: period.to,
      currency: baseCurrencyOf(db.state, userId),
      summary: summarize(budgets, daysLeft(period, today)),
    }
  })

  router.on('POST', '/v1/budgets', ({ db, userId, body }) => {
    const row: BudgetRow = {
      id: newId('bud'),
      userId,
      currency: baseCurrencyOf(db.state, userId),
      ...validateBudget(db, userId, body),
    }
    db.state.budgets.push(row)
    db.save()
    return viewOf(db, userId, row)
  })

  router.on('POST', '/v1/budgets/copy', ({ db, userId, body }): BudgetCopyResult => {
    const target = readPeriod(objectBody(body).period)
    const source = shiftPeriod(target, -1, monthStartOf(db.state, userId))
    const base = baseCurrencyOf(db.state, userId)
    const own = db.state.budgets.filter((row) => row.userId === userId)
    const taken = new Set(own.filter((row) => row.period === target).map((row) => row.categoryId))
    const copies = own
      .filter((row) => row.period === source.key && !taken.has(row.categoryId))
      .map(
        (row): BudgetRow => ({
          id: newId('bud'),
          userId,
          categoryId: row.categoryId,
          period: target,
          limit: limitIn(db.state, row, base, source),
          currency: base,
        }),
      )
    if (copies.length === 0) badRequest({ period: ['validation.nothingToCopy'] })
    db.state.budgets.push(...copies)
    db.save()
    return { copied: copies.length }
  })

  router.on('PUT', '/v1/budgets/:id', ({ db, userId, params, body }) => {
    const row = ownBudget(db, userId, params.id)
    Object.assign(row, validateBudget(db, userId, body, row), { currency: baseCurrencyOf(db.state, userId) })
    db.save()
    return viewOf(db, userId, row)
  })

  router.on('DELETE', '/v1/budgets/:id', ({ db, userId, params }) => {
    const row = ownBudget(db, userId, params.id)
    db.state.budgets = db.state.budgets.filter((budget) => budget.id !== row.id)
    db.save()
  })
}

import { currentPeriodKey, type MonthStart } from '~/shared/period/period'

export function useBudgetPeriod(monthStart: Ref<MonthStart>) {
  const route = useRoute()
  const router = useRouter()
  const current = computed(() => currentPeriodKey(monthStart.value))

  const period = computed({
    get: () => resolvePeriodKey(route.query.period, current.value),

import { useCategories } from '~/shared/categories/useCategories'
import { shiftPeriod } from '~/shared/period/period'
import { useUserSettings } from '~/shared/user/useUserSettings'
import { budgetableCategories } from '../utils/budgetView'

export function useBudgetsScreen() {
  const settings = useUserSettings()
  const categories = useCategories()
  const ready = computed(() => !settings.isPending.value && !settings.isError.value)
  const { period, current } = useBudgetPeriod(settings.monthStart)
  const list = useBudgets(period, { enabled: ready })
  const previousKey = computed(() => shiftPeriod(period.value, -1, settings.monthStart.value).key)
  const isEmpty = computed(() => list.page.value !== undefined && list.items.value.length === 0)
  const previous = useBudgets(previousKey, { enabled: computed(() => ready.value && isEmpty.value) })
  const canCopy = computed(() => isEmpty.value && (previous.page.value?.total ?? 0) > 0)

  const cards = computed(() =>
    list.items.value.map((budget) => ({ budget, name: categories.nameOf(budget.categoryId) ?? '' })),
  )
  const available = computed(() => budgetableCategories(categories.categories.value, list.items.value))

  const isError = computed(() => settings.isError.value || list.isError.value || categories.isError.value)
  const isPending = computed(
    () => !isError.value && (settings.isPending.value || list.isPending.value || categories.isPending.value),
  )

  function retry() {
    if (settings.isError.value) settings.refetch()
    if (list.isError.value) list.refetch()
    if (categories.isError.value) categories.refetch()
  }

  return {
    period,
    current,
    previousKey,
    monthStart: settings.monthStart,
    page: list.page,
    cards,
    available,
    isEmpty,
    canCopy,
    isPending,
    isError,
    ready,
    retry,
  }
}

import type { BudgetDto, BudgetInput, CategoryDto } from '~/shared/api/contract'
import { categorySwatchClass } from '~/shared/categories/colors'
import { type Currency, fromMinor, toMinor } from '~/shared/money/money'
import { BUDGET_LIMIT_MAX, type BudgetForm, budgetRules } from '../schemas/budgetSchema'

const props = defineProps<{
  budget?: BudgetDto
  categoryName?: string
  period: string
  categories: CategoryDto[]
  currency: Currency
}>()
const visible = defineModel<boolean>('visible', { required: true })
const emit = defineEmits<{ manageCategories: [] }>()
const { t, locale } = useI18n()
const notify = useNotify()
const confirm = useConfirm()
const server = useServerErrors()
const { create, update, remove } = useBudgetMutations()

const fields = ['categoryId', 'limit'] as const
type Field = (typeof fields)[number]

const form = reactive<BudgetForm>({ categoryId: null, limit: null })
const v$ = useVuelidate(budgetRules(t), form)
const formEl = ref<HTMLFormElement | null>(null)

const isEdit = computed(() => props.budget !== undefined)
const noChoices = computed(() => !isEdit.value && props.categories.length === 0)
const saving = computed(() => create.isPending.value || update.isPending.value || remove.isPending.value)

function reset() {
  const budget = props.budget
  Object.assign(
    form,
    budget ? { categoryId: budget.categoryId, limit: fromMinor(budget.limit) } : { categoryId: null, limit: null },
  )
  server.clear()
  v$.value.$reset()
}

watch(visible, (open) => {
  if (open) reset()
})

const errorsOf = (field: Field) => [
  ...v$.value[field].$errors.map((error) => String(unref(error.$message))),
  ...server.messages(field),
]

function touch(field: Field) {
  v$.value[field].$touch()
  server.clear(field)
}

const close = (message: string) => {
  notify.success(message)
  visible.value = false
}

async function showServerErrors(error: unknown) {
  if (server.apply(error, fields)) {
    await nextTick()
    focusFirstInvalid(formEl.value)
  } else notify.error(error)
}

async function submit() {
  server.clear()
  if (!(await v$.value.$validate())) {
    await nextTick()
    focusFirstInvalid(formEl.value)
    return
  }
  const budget = props.budget
  const input: BudgetInput = {
    categoryId: form.categoryId ?? '',
    period: budget?.period ?? props.period,
    limit: toMinor(form.limit ?? 0),
  }
  if (budget) {
    update.mutate(
      { id: budget.id, input },
      { onSuccess: () => close(t('budgets.toast.updated')), onError: showServerErrors },
    )
  } else {
    create.mutate(input, { onSuccess: () => close(t('budgets.toast.created')), onError: showServerErrors })
  }
}

function confirmDelete() {
  const budget = props.budget
  if (!budget) return
  confirm.require({
    header: t('budgets.confirm.deleteTitle'),
    message: t('budgets.confirm.deleteMessage', { name: props.categoryName ?? '' }),
    acceptLabel: t('budgets.actions.delete'),
    rejectLabel: t('shared.actions.cancel'),
    acceptProps: { severity: 'danger' },
    rejectProps: { severity: 'secondary', outlined: true },
    accept: () =>
      remove.mutate(budget.id, {
        onSuccess: () => close(t('budgets.toast.deleted')),
        onError: (error) => notify.error(error),
      }),
  })
}

function manageCategories() {
  visible.value = false
  emit('manageCategories')
}

## What changed and why

Budgets now work end to end on the mock backend. Each budget is a monthly limit for one expense category in a financial period, so it follows the user's month start. The list endpoint returns what the screen needs in one go: spent from the period's expenses, what is left, a status (on track below 85%, almost spent up to 100%, over budget above that), a per-day hint and a period summary.

- One budget per category and period, expense categories only, never the transfers category.
- Deleting a category moves its budgets to "Other" and adds the limits up when "Other" already has a budget in that period.
- Limits are re-priced at the period's first-day rate if the base currency changes; changing the month start re-ranges the same period.
